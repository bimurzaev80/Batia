Вариант 1 — быстрый старт

GitHub Pages + экспорт JSON + папка на Яндекс.Диске
  1. Оставь сайт на GitHub Pages.[web:248]
  2. В дашборде используй экспорт JSON после важных изменений.
  3. На Яндекс.Диске создай папки: Batya/Progress, Batya/Reviews, Batya/Consultations, Batya/Videos.[web:288]
  4. Сохраняй JSON в Progress, тяжёлые материалы — по своим папкам.
Плюс: запустишься сегодня. Минус: сохранение не автоматическое.

Вариант 2 — нормальная рабочая система

GitHub Pages + Supabase + Яндекс.Диск как архив
  1. Создай проект в Supabase Dashboard.[web:287]
  2. Создай таблицу задач и bucket для JSON/вложений или хотя бы bucket для файлов.[web:284][web:289]
  3. Подключи сайт к Supabase через публичный anon key, а service key не используй в браузере.[web:284][web:289]
  4. Яндекс.Диск оставь для резервного хранения исходников и закрытых материалов.[web:285][web:290]
Это лучший баланс: структура живёт в Supabase, тяжёлые архивы — в Диске.

Инструкция: Supabase по шагам

  1. Зайди в Supabase и нажми New project.[web:287]
  2. После создания проекта открой Storage → New Bucket и создай bucket, например batya-files.[web:284]
  3. Открой Project Settings → API, сохрани Project URL и anon key.
  4. Эти два значения можно безопасно использовать на фронтенде; service role key — нельзя.[web:284][web:289]
  5. Позже в код сайта добавляется клиент Supabase и кнопка «Сохранить в облако».

Инструкция: Яндекс.Диск по шагам

  1. Создай отдельную папку под систему Батя.
  2. Если хочешь только ручное хранение — API не нужен, просто сохраняй туда JSON и материалы.
  3. Если хочешь автозагрузку, придётся делать OAuth-приложение и выдавать права Disk API.[web:288][web:290]
  4. Не храни OAuth-токен Яндекс.Диска прямо в HTML на GitHub Pages — это небезопасно.[web:285][web:290]
  5. Для автоматизации Яндекс.Диска лучше использовать промежуточный сервер или serverless-функцию.
